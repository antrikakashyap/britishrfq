# Demo video: voice-over script and pitch kit

The video [`demo.mp4`](demo.mp4) is **3:43 long, 1080p, silent**. There is no AI voice. This page has the words for you to say, with the exact time each part starts, so you can record your own voice and lay it on top.

## How to use this in 3 steps

1. **Watch the video once** with this page open, so you know what appears on screen.
2. **Record your voice.** Easiest way: record one short clip per scene (10 clips) and read the *Say this* text. Speak slowly and calmly. Every scene has been timed for about 1.9 words per second, which is a relaxed pace, so you will fit.
3. **Put the clips on the video** at the start times in the table below (any editor works: CapCut, DaVinci Resolve, iMovie, or the one-line command at the end of this page).

> Tip: stand up, smile a little, and read it like you are explaining it to a friend. You do not need to read word for word. Keep the ideas, use your own words.

## If you have 60 seconds

> Buyers who ship freight ask several carriers for a price. A British auction makes them compete in the open: everyone sees the ranking, and a supplier can only lower its own price.
>
> The clever part is time. If something happens in the last X minutes, the auction is extended by Y minutes. That stops last-second bids. But there is also a forced close, a hard deadline that nothing can cross, so the auction always ends.
>
> You choose what counts as activity: any bid, any change in the ranking, or only a new lowest bidder. Every extension is written to a log with the reason.
>
> It is React and Node with TypeScript, with sixty automated tests and a real-time end-to-end run. It is deployed and you can try it now.

## Questions you may be asked (with simple answers)

| Question | A good short answer |
| --- | --- |
| **What problem does this solve?** | Buyers want the best price. When carriers can see each other and respond, prices fall. Extra time near the end stops last-second tricks, so the competition is fair. |
| **What stops the auction from running forever?** | The forced close. The close time can never go past it. This is enforced in the code and again in the database, so even a bug cannot break it. |
| **What is the difference between the three triggers?** | "Bid received" extends on any bid. "Rank change" extends only if the order of suppliers changes. "L1 change" extends only if a new supplier becomes the lowest. They only matter inside the last X minutes. |
| **What if two suppliers bid at the same moment?** | Each bid is one database transaction and the server is the only clock. Bids are handled one at a time, so nothing is lost or mixed up. I tested 60 bids sent at once. |
| **Why does the server keep the time, not the browser?** | A laptop clock can be wrong or changed. The server stamps every bid, and the countdown on the page is corrected using the server's time. |
| **How did you test something that depends on time?** | The rules take the time as an input, so unit tests can check to the millisecond. I also wrote an end-to-end script that runs real auctions for about 3.5 minutes. All 39 checks pass. |
| **How does it scale?** | One server with SQLite is perfect for this size. A bid costs about 13 ms even with 3,000 bids in one auction. For many servers I would move to Postgres and a shared message channel. The design notes describe the steps. |
| **Why SQLite?** | No extra server to run, and transactions are safe. It keeps the project easy to install and review. |
| **What is missing?** | Logins. Today, suppliers are identified by the carrier name they type, because the brief does not ask for accounts. I would also add a buyer flow to award the winner. |
| **What did you decide where the brief was unclear?** | They are listed in the README. For example: a "rank change" includes a new supplier joining, the first bid counts as an L1 change, and a supplier can only lower its own price. |
| **What was the hardest bug?** | Speed: every bid re-ranked every old bid. I changed it to look only at each supplier's best bid, which made it about four times faster and the page data five times smaller. |
| **How do you know it is accessible?** | I ran an automated WCAG scan on every page, desktop and phone. It found one issue (a scrolling list you could not reach by keyboard) and I fixed it. It now shows zero violations. |

## Add your voice to the video

If your recording is one file (for example `voice.wav`) that already matches the timings above:

```bash
ffmpeg -i demo.mp4 -i voice.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest demo-voiced.mp4
```

If you recorded one clip per scene, drop them into any video editor at the start times above.

## Record the video again

The video is generated by a script, so you can redo it after any change to the app. It drives a real browser against a running copy of the app.

```bash
npm run build
PORT=8123 npm start &                       # a fresh server with demo data
npm i --no-save playwright && npx playwright install chromium     # one time; also needs ffmpeg
BASE=http://localhost:8123 OUT=docs/demo/demo.mp4 node scripts/demo/record.cjs
```

The words in the script live in `scripts/demo/record.cjs` (the `SAY` list). After a new recording, the timings in `docs/demo/demo.marks.json` are updated; copy them into this page.
